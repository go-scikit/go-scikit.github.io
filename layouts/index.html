    Roadmap
    
Parity with MATLAB and Mathematica, in four waves.

    
The goal is feature parity with MATLAB (base and toolboxes) and Mathematica, in pure Go (CGO=0), each piece validated against the reference tools of its domain. The plan, the home of each domain and the order of the work are in the roadmap repository: PLAN.md, STATUS.md and the bibliography. Five packages of the new organisations have been released: go-approx/interp v0.2.1 (speed comparison in its docs/perf.md), go-approx/poly, go-dsp/signal and go-sparse/sparse v0.1.0, each at or below its reference's time on every case measured, and go-bignum/bigfloat v0.1.0, at or below mpmath's time on every function (docs/perf.md). The vector-update kernels Axpy, Xpby, AxpyDot and Scale shipped in go-simd/floats v0.4.0.

    Get started
    
A first notebook, in four commands.

    
A notebook is a Markdown file; its go and ruby blocks are the cells. Put the notebook from the top of this page in first.md, in a module that requires the libraries its Go cells import, and run it. It prints the quartiles of a thousand normal draws from seed 42 (the draws SciPy's norm.rvs(10, 2, size=1000, random_state=np.random.default_rng(42)) makes), then fits a normal distribution to the same draws in Ruby.

    

      
shell


$ go install github.com/go-notebook/notebook/cmd/notebook@latest
$ go mod init example.com/first
$ go get github.com/go-statistics/stats github.com/go-ndarray/ndarray
$ notebook run first.md
{{ $out }}
# notebook html first.md    writes first.html
# notebook serve first.md   the same, live in the browser, editable

    

    
Run it again and every cell is kept: a cell whose code and inputs did not change is not run again, across runs. The go-notebook documentation gives the cell rules; to try the arrays and the transforms without installing anything, the go-ndarray and go-fft playgrounds run them compiled to WebAssembly in the browser, and the go-notebook, go-statistics and go-numerics playgrounds run whole notebooks there, Go and Ruby cells alike: edit the cells, run them, see the figures.

    
A ruby cell runs on go-embedded-ruby, a Ruby written in Go, so the notebook stays one Go program with no Ruby to install. It sees the values the Go cells above it defined (here x, a Go []float64), and the Go cells below it see what it defines; the kernel orders and re-runs cells of both languages by what they use. From Ruby, the stack is reached through go-scikit/ruby, which the kernel adds by itself: Stats, Special, Optimize, Integrate, DataFrame and Plot call the same Go functions, with the same answers. The Ruby cells page gives the rules, and the -timeout and -memory limits that stop a runaway cell.
